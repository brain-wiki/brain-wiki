# Open questions

Questions that change the design or its defaults. Each has a status and a recommendation. Settled questions stay listed so their ids keep pointing somewhere.

| # | Question | Options | Status and recommendation |
|---|---|---|---|
| Q1 | How should session capture work when it is turned on? | — | Decided: there is no capture. It was removed with the other host hooks ([proposal](../proposal/hooks.md)), and harvest covers the same sessions afterwards (D20). |
| Q2 | Should consolidation runs that touch episodes with external inputs wait for review by default (`review_external`)? | No, and mark their claims `[unverified]`; yes, every such run waits for review | Decided: withdrawn in format 3. Consolidation has no review step and `[unverified]` is gone (D34). Rules still need the user's own words. |
| Q3 | How should privacy work inside a brain? | Ordered levels per topic and note with a maximum per host (shipped, then removed); a model built on who receives content | Open. Levels stay removed until a design says what each one protects against ([proposal](../proposal/privacy.md)). |
| Q4 | Should guard counts that reveal a hidden superseding note be kept? | Keep the counts; hide them completely | Open, but moot until privacy inside a brain returns (Q3). |
| Q5 | What level of Windows support? | Full; best effort | Open. Recommendation: best effort. CI runs on Linux and macOS only, and `brain schedule` refuses to run on Windows. |
| Q6 | Ship an npm launcher (`npx brain-wiki`)? | Ship it; defer | Open. Recommendation: defer, because `uvx` already runs brain-wiki without an install. |
| Q7 | Where is the project published? | A personal GitHub account; an organization | Decided (D24): the `brain-wiki` organization, `github.com/brain-wiki/brain-wiki`, with the MCP Registry name `io.github.brain-wiki/brain-wiki`. |
| Q8 | Should harvest distill sessions with a model by default, or write them raw? | Distill with a preset (cleaner episodes, model cost); raw (no model, longer episodes) | Replaced by [D36](../decision/d36-harvest-into-notes.md): harvest writes no episodes; the agent whose sessions they are files them into notes. `brain harvest` lists the sessions with token estimates. |
| Q9 | Where does knowledge that agents learn live? See [overview §2.1](../design/overview.md#21-two-uses). | (a) Mixed into the user's topics, with nothing telling them apart. (b) Topics owned by agents, marked with a topic flag such as `owner = "agents"`: agents grow them freely, while user topics gain only inbox episodes. (c) A separate brain per agent or fleet, marked in its manifest with `kind = "agent"`. | Open. Recommendation: (b), with (c) available through the same flag on a whole brain. One brain stays the default, user notes are protected from agent sprawl, and a standalone agent can still own a brain. |
| Q10 | Should retrieval weigh who wrote a note? | (a) No, rank by relevance only, as today. (b) Label each result with its origin, without changing rank. (c) Also rank the user's notes above agents' notes on ties. | Open, waiting on Q9. Format 3 records no origin per note (D33), so there is nothing to label or rank by. Git history and `bw-sources` are the only record of who wrote what. |
| Q11 | How do facts about the outside world stay current? Versions, APIs, prices, and people's roles go stale without anyone noticing. | (a) Rely on supersession when someone notices. (b) A review date and source URL per fact, flagged by lint when past due, and a pass that re-checks them against their sources. (c) Ranking that decays with age. | Open. Option (b) was designed around per-claim metadata, which format 3 removed. Notes can cite URLs in `bw-sources`, but no note-level review date or lint check is designed. |
| Q12 | What may agents learn without the user? Rules always need the user's words, but agents also learn procedures, such as "tests in this repo need the emulator". | (a) Procedures are ordinary notes, found by search. (b) A `howto` note type that orientation shows for the matching project, below the rules and never as a directive. (c) Agents propose rules for the user to approve, and nothing else. | Open. Recommendation: (b), so agents get their own lessons back at session start without the authority of rules. Today `howto` is an ordinary type and orientation does not list such notes. |
