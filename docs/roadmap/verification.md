# Verification items

Facts about hosts and dependencies that documentation could not confirm. Each is checked by a test or a manual run, and the design follows the result. An item with a bold result is answered.

| # | Question | Result or test |
|---|---|---|
| T-1 | Does Antigravity accept a root `plugin.json` with Agent Plugins fields (`$schema`, `version`, `extensions`)? Its published schema is closed. | **Verified** (agy 1.3.3, 2026-10-11). `agy plugin install` accepts the full manifest. In a session the agent lists the plugin's three skills, calls its MCP tools, and gets its `always_on` rules. |
| T-2 | Does Antigravity expand a plugin-root variable in the plugin's `mcp_config.json` and `hooks.json`, and what working directory do plugin hooks get? | **Verified** (agy 1.3.3). No plugin-root variable is set. Hook commands run through a shell with the plugin folder as working directory, the host's environment, `ANTIGRAVITY_CONVERSATION_ID`, and stdin closed after the payload. The project comes from the payload's `workspacePaths`. brain-wiki ships no hooks now. |
| T-3 | What is the line schema of Antigravity's transcript JSONL? | **Verified** for structure (2026-10-11). Steps carry `step_index`, `source`, `type`, `status`, `created_at`, and `content`. Types include `USER_INPUT`, `PLANNER_RESPONSE` (with `tool_calls`), `EPHEMERAL_MESSAGE`, and tool steps; MCP calls are `call_mcp_tool` with `ServerName`, `ToolName`, and `Arguments`. `transcript.jsonl` cuts long steps to about 4 KB, so the reader prefers `transcript_full.jsonl`. Since 1.3 the CLI writes `conversation_summaries.db` with `workspace_uris`, so its conversations route by working directory. |
| T-4 | Does any host load a plugin-root `AGENTS.md` or `GEMINI.md` into sessions? | **No** for the Antigravity CLI, though the same plugin's `always_on` rule loaded. Other hosts not tested. |
| T-5 | Can an Antigravity headless run be limited to no tools (a custom agent with `tools: []`)? | **No** (agy 1.3.3). With `tools: []` or `tools: [finish]`, all 59 tools stayed listed. A tool call that headless mode denies ends the turn with no output, so every preset prompt starts with a preamble telling the model not to call tools. |
| T-6 | What is the line schema of Codex rollout files, how does a session id map to a file, and how are subagent threads marked? | Open. Record fixtures from current Codex releases and test the reader against them. |
| T-7 | Which marketplace file does `codex plugin marketplace add` read from a repository: `.agents/plugins/marketplace.json` only, or also `.claude-plugin/marketplace.json`? | Open. Add the repository as a marketplace in a scratch Codex config. |
| T-8 | Which hosts support elicitation for `brain_propose_rule` confirmation? | **Antigravity CLI:** it declares elicitation support but declines every request without showing anything, so the server gives Antigravity clients the proposal fallback. Claude Code and Codex not tested. |
| T-9 | What hook timeouts and output limits do hosts enforce? | **Antigravity:** a hook past its timeout is killed and its output dropped, and the model call proceeds. Hooks run one after another before every model call. An `ephemeralMessage` is cut at about 49 KB. Other hosts not tested; brain-wiki ships no hooks now. |
| T-10 | Does `uvx --from brain-wiki==<version> brain …`, as marketplace installs run it, start fast once cached? | **No** (Linux, 2026-10-11). Online `uvx` checks the package index on every call, which took 23 s behind a slow index even when cached. `uvx --offline` takes 0.13–0.21 s and an installed `brain` 0.08–0.11 s. This killed hooks, which were later removed, and slows the MCP server's start (D23). macOS not timed. |
| T-11 | How much does the Claude Code transcript format vary across versions? Its docs call the format internal. | Open. Collect fixtures from several releases and run the reader tests against all of them. |
| T-14 | Does Obsidian treat links in list properties as links, in backlinks and the graph, and rewrite them on rename? | Open. In format 4 only the relation fields (`bw-part_of`, `bw-depends_on`, `bw-conflicts_with`, `bw-superseded_by`) and `bw-sources` hold links in properties, as bare `"[[note]]"` values. Open a format 4 brain as a scratch vault, rename a note one of them names, and check the property, the backlinks pane, and the graph. |
| T-15 | Does Codex put the MCP server's `instructions` into the model's context, and does the agent act on them? brain-wiki relies on this instead of writing `AGENTS.md` for Codex ([Codex](../design/hosts/codex.md#1-instructions-come-from-the-mcp-server)). | Open. In a scratch Codex session with the plugin, ask about a past decision and check that the agent calls `brain_list` and `brain_orient` first. |
